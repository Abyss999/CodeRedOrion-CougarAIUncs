# Food Waste Reducer: agent rules

iOS app that tracks fridge and pantry food, predicts expiry, flags spoilage from photos, suggests
recipes from expiring items, and lets friends and groups share surplus. Removing food with an
outcome is how waste is measured. Product: [`docs/IDEA.md`](docs/IDEA.md). Status:
[`HANDOFF.md`](HANDOFF.md). Screens: [`docs/design/SCREENS.md`](docs/design/SCREENS.md).

## Rules
- Secrets live in `.env` only (and as Colab secrets for training). Never hardcode, commit or print
  them. Keep `.env.example` current with placeholders.
- Run Python from the project venv (`.venv`, `.venv-ml`), never the global interpreter. Pin every
  dependency.
- Any change to architecture, endpoints, schema, setup or the ML data contract updates `docs/` in
  the same PR.
- Update `HANDOFF.md` at the end of every work session.
- Feature branches and PRs into `main` only. Never push to `main`. Small commits with clear
  messages.
- Verify before claiming done: run the code, hit the endpoint, build the app. A builder's own
  check doesn't count; a QA sign-off does.
- Before pulling images, models or datasets, check free disk space. Delete only what you created.
- Never kill processes by pattern. Record the PID of anything you start and kill only that.

## Stack
| Layer | Choice |
|---|---|
| iOS | SwiftUI, **minimum iOS 18**, built with **Xcode 26 / iOS 26 SDK**, project generated by XcodeGen from `ios/project.yml` (`.xcodeproj` and `Info.plist` are generated and gitignored) |
| Signing | **Free Personal Team** via gitignored `ios/Local.xcconfig`. No TestFlight. Never add capabilities a free team can't sign (push, iCloud, App Groups, Sign in with Apple) |
| Auth | Email + password, and **Google Sign-In**. No Apple sign-in |
| API | Flask app factory, SQLAlchemy + Flask-Migrate, gunicorn in Docker. Migrations run on container start |
| DB | PostgreSQL + TimescaleDB, one database. `food_events` is a hypertable |
| AI | Gemini (`GEMINI_MODEL`, see `docs/DECISIONS.md`) behind `services/gemini.py`, which logs token usage |
| Vision | Ultralytics YOLO26 (version pinned in `ml/yolo/requirements.txt`), trained on Colab |
| OCR | `zai-org/GLM-OCR`, then the deterministic receipt parser |
| Runtime | Docker Compose, ports bound to `127.0.0.1`. Phone demo goes through `scripts/demo_tunnel.sh` |

## Process
- The orchestrator plans, rules on disputes, reviews and **merges**. Builder sessions open PRs and
  never merge. Sub-agents never run git.
- Every builder is paired with a QA agent that starts at the same time, in the same worktree, and
  writes only in its own paths. **QA never edits feature code.**
- Never let two agents edit the same file. Anything outside your paths is a request to its owner.
- One heavy run at a time: Docker builds, full test suites, training.
- Backend tests use `TEST_DATABASE_URL` only. The suite rebuilds that schema under an advisory
  lock. Never touch it from outside the suite.
- Agents report against the API contract in `docs/API.md`. When code and contract disagree, the
  orchestrator rules and the contract is updated in the same PR.
- Work ported from someone else carries `Co-authored-by: <their GitHub noreply email>` on every
  ported commit.
- Never delete a branch that an open PR targets.

## Merge gate
- A PR merges only with a QA pass recorded in `docs/qa/<area>.md`, then folded into
  [`docs/QA.md`](docs/QA.md), plus green CI.
- A QA failure goes back to the builder. It's never merged around.
- Anything that breaks the demo path is a blocker: photo add → expiry prediction → remove → Impact.
- Thresholds and data rules live in `docs/QA.md`, including the leakage, stratification and binary
  freshness gates. Metrics from a split that fails them are invalid and must not be quoted.
- Parser changes are measured on a **blind** holdout the builder has never seen. A holdout used
  for fixing is no longer blind.

## Core domain rules
- Removal is a soft delete: `outcome ∈ {used, donated, thrown_out}`. `waste_reason` is required
  if and only if the outcome is `thrown_out`.
- Every removal writes exactly one `remove` event in the same transaction. A `donated` removal
  fulfils an open share listing. Undo (`/restore`) must leave impact exactly as it was before.
- Impact is computed from `food_events`, never stored as totals.
- Freshness is `fresh | semi_fresh | spoiled`. `semi_fresh` shows as "Use soon". YOLO gates are
  spoiled vs not-spoiled.
- Visibility: friend-scoped items are visible to accepted friends only, group-scoped items to
  current members only. A listing or request the caller can't see returns 404.

## Design and UI
- The design canvas (https://claude.ai/artifact/ALmB8FYKGrayhDQXqvoncx) and `docs/design/` are
  the source of truth. iOS builds only approved screens.
- Translate designs into native SwiftUI. Every colour, size and font comes from
  `ios/App/Theme.swift`, which mirrors `DESIGN_SYSTEM.md`. No ad-hoc values in views.
- Use native components where the design system says so: the glass `TabView` (Add is a tab that
  presents a sheet), sheets, swipe actions, `ContentUnavailableView`, data scanner, document
  camera, and the official Google button.
- Every data screen has empty, loading (skeleton) and error states.
- Accessibility is required: VoiceOver labels, Dynamic Type to AX5, 44 pt targets, AA contrast,
  and colour never the only cue.
- An iOS PR that deviates from an artboard includes a **Design delta** section with a Simulator
  screenshot. The orchestrator updates the canvas on merge.
- Never run Impeccable while generating UI. UI review (Impeccable critique and polish, then
  web-design-guidelines) runs once, when the UI is feature-complete.

## Conventions
- API: JSON, `snake_case`, ISO-8601 UTC, JWT bearer, errors as
  `{"error": {"code", "message"}}` with the right status code.
- Python: blueprints in `routes/`, logic in `services/`, and one service module per external
  dependency, so tests can stub it.
- Swift: one view per file. `APIClient` protocol with Live and Mock clients. Stable
  `accessibilityIdentifier`s (`screen.element.id`).
- Tests: `backend/tests/test_<area>.py`, `ios/Tests/{UnitTests,UITests}`, `ml/eval/tests`,
  `pipeline/tests`.
